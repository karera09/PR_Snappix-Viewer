# post.md フォーマット仕様（外部ツール開発者向け）

Snappix Viewerは、**フォルダに `post.md` が無い状態を基本**として動作する汎用の画像ビューアーです。フォルダ直下に `post.md`（本仕様に従うメタデータファイル）が存在する場合、そのフォルダは「投稿フォルダ」として認識され、以下の**追加機能が解放**されます。

- タイトル・投稿日・タグ・プラン・お気に入り数などのメタ情報表示（タイルのキャプション/詳細）
- 投稿日でのソート・期間フィルター
- 本文（Markdown）のプレビュー表示と本文検索（絞り込み欄の `body:` 構文）
- 投稿 URL → ローカルフォルダの逆引き（本文中の投稿リンクをローカルで開く）
- ライブラリ健全性チェックへの文脈付与（検出された問題に `service` / `post_id` / `creator` を添える。`.part` 残骸・0 バイトファイル・空フォルダの検出自体は `post.md` を必要としません）
- 代表サムネイルの指定（`#thumb#` プレフィックス規約）

外部ツールが本仕様に従って `post.md` を書き出せば、Snappix Viewerはそのライブラリを追加設定なしで活用できます。

## 1. 配置とエンコーディング

- 1 投稿 = 1 フォルダ。フォルダ直下にファイル名 **`post.md`**（固定・小文字）を置く。
- エンコーディングは **UTF-8（BOM なし）**、改行は LF を推奨（CRLF も許容）。BOM 付き UTF-8 も読み取り側で許容する（先頭の BOM は無視される）が、推奨はしない。
- 同フォルダ直下に投稿の画像・添付ファイルを置く（サブフォルダも閲覧可能だが、メタ情報はフォルダ直下の `post.md` のもののみ適用される）。

## 2. 全体構造

```markdown
# 投稿タイトル

- post_id: 123456
- url: https://fantia.jp/posts/123456
- creator: クリエイター名 (creator_id)
- service: fantia
- posted_at: 2026-01-02T03:04:05+09:00
- plan: プラン名
- plan_price: ¥500
- tags: タグA,タグB
- locked_contents: 0
- favorites: 42
- downloaded_at: 2026-07-01T12:00:00+09:00

本文テキスト（Markdown）…

![](./image%20name.jpg)
```

構造は上から順に:

1. **タイトル行** — `# ` で始まる H1 見出し 1 行。
2. **先頭メタブロック** — `- key: value` 形式の行の連続。**ブロック内に空行を挟んではいけません**（タイトルとメタブロックの間の空行は許容）。
3. **本文** — メタブロック終端以降はすべて本文。Markdown として解釈・表示される。

### 先頭メタブロックの境界規則（重要）

パーサは**先頭のメタブロックのみ**を読み取ります。メタブロックは**空行を含まない `- key: value` 行の連続**です。

- タイトル行と最初のメタ行の間の空行は許容されます（走査はスキップして続行）。
- **メタ行を 1 つ以上読んだ後に空行が現れた時点で、メタブロックは終了**します。それ以降の行は（`- key: value` 形式でも）すべて本文です。
- 空行でなくても、`- key: value` にマッチしない行に到達した時点でブロックは終了します。
- **行の区切りは Python の `str.splitlines()` 準拠**です（`LF` / `CRLF` / 単独 `CR` に加え、`VT`・`FF`・`U+0085`・`U+2028`・`U+2029` も 1 行の終わりとして扱われます）。メタ値にこれらを含めないでください（含めるとその位置で行が割れ、以降のメタ行は本文になります）。

このため本文中の箇条書き（`- 補足: …` など）がメタ行として誤認・上書きされることはありません。逆に言うと、**すべてのメタ行は空行を挟まず連続させ、本文より前に置く**必要があります。メタブロックの途中に空行を挟むと、それ以降のメタ行は本文として扱われます（部分更新〔§7〕でも同じ境界規則で先頭ブロックだけが対象になります）。

## 3. メタキー一覧

すべて省略可能です（キーが無くても該当機能が使えないだけで、エラーにはなりません）。書き出し順は以下を推奨します。

| キー | 型・書式 | 用途 |
|---|---|---|
| `post_id` | 文字列（空白なし） | 投稿 ID。URL 逆引き・健全性チェックの文脈情報 |
| `url` | URL | 投稿の元 URL |
| `creator` | `名前 (creator_id)` | クリエイター表示名と ID。ID は末尾の丸括弧から抽出される |
| `service` | 小文字英数字（例: `fantia` / `fanbox` / `patreon`） | サービス識別子 |
| `posted_at` | ISO 8601（タイムゾーン付き推奨） | 投稿日時。ソート・期間フィルターに使用 |
| `plan` | 文字列 | プラン/ティア名（キャプション表示） |
| `plan_price` | 文字列 | プラン価格（キャプション表示）。通貨記号を含む表示用の値（例: `¥500` / `$5`）でも、裸の数値（例: `500`）でもよく、パーサは前後の空白を落として verbatim な文字列として保持します（数値としての解釈・正規化は行いません） |
| `tags` | カンマ区切り | 投稿タグ。検索対象 |
| `locked_contents` | 非負整数 | 未取得（ロック）コンテンツ数。🔒バッジ表示 |
| `favorites` | 非負整数 | お気に入り/いいね数。♡バッジ表示・ソートに使用 |
| `downloaded_at` | ISO 8601 | 取得日時（外部ツールの差分管理用。ビューアは表示に使わない） |

- 値の前後の空白は無視されます。
- 未知のキーは無視されます（将来拡張可）。キー名は `[a-z_]+` に限ります。

## 4. 本文と画像参照

- 本文は Markdown として描画されます（見出し・リスト・リンク等）。
- 同フォルダ内の画像を参照する場合は、**相対パス + 全文字パーセントエンコード**の形式を使います:

  ```
  ![](./{urllib.parse.quote(filename, safe="")})
  ```

  例: `image name.jpg` → `![](./image%20name.jpg)`。スペース・`#`・日本語ファイル名でもリンクが壊れません。
- `./` で始まる相対参照のみが「投稿ローカル画像」として扱われます（絶対 URL の画像はサムネイル候補になりません）。

## 5. 代表サムネイル規約（`#thumb#`）

ファイル名が `#thumb#` で始まる画像（例: `#thumb#cover.jpg`）は、そのフォルダの**代表サムネイル**として扱われます。

- フォルダタイルのサムネイルとして最優先で使用されます。
- 通常の画像一覧からは除外できます（ビューア設定「`#thumb#` を除外」）。
- `#` はほとんどのファイルシステム（NAS の ext4/XFS 含む）で合法な文字です。

## 6. 投稿 URL の逆引き

ビューアは本文中の投稿 URL をローカルフォルダに解決する索引を持ちます。組み込みで認識される URL パターン:

- Fantia: `https://fantia.jp/posts/{post_id}`
- Pixiv Fanbox: `https://{creator}.fanbox.cc/posts/{post_id}` / `https://www.fanbox.cc/@{creator}/posts/{post_id}`
- Patreon: `https://www.patreon.com/posts/{slug-}{post_id}`

`service` + `post_id` の組がこれらと一致する `post.md` を持つフォルダが逆引き先になります。

## 7. 既存ファイルの部分更新（外部ツール向けの推奨動作）

メタ値のみ更新したい場合（お気に入り数の更新等）は、**先頭メタブロック内の該当行だけを差し替え**、タイトル・本文・他のメタ行はバイト単位で保持することを推奨します。キーが存在しない場合は、最後のメタ行の直後に挿入します。この規則に従う限り、ビューア側のキャッシュ（フォルダプレビュー・検索索引）は mtime 変化で自動的に追従します。

**値に改行を含めてはなりません。** メタ行は 1 キー = 1 行の契約です。改行を含む値をそのまま書き込むと行が割れ、後続のメタ行がすべて本文として解釈されます（悪意ある値なら別キーのメタ行を注入することさえできます）。サイト API 等の制約のない文字列を値にする書き手は、**改行を空白へ畳んでから**（例: `" ".join(value.splitlines()).strip()`）書き込んでください。タイトル（H1 見出し）も同じ理由で単一行に畳む必要があります。

## 8. 互換性の注意

- ビューアのパーサは寛容です: メタブロックが無い/壊れている `post.md` でも、タイトルと本文の表示は可能な範囲で行われます。
- メタデータの読み取り方法は用途によって異なります。**投稿メタ表示**（情報パネル。`read_post_meta`）・**投稿日ソート／期間フィルター**・**フォルダプレビュー**（タイルのキャプション／サムネイル解決）と**投稿 URL の逆引き**〔§6。`read_post_ref` / `read_post_identity`〕に使う `service` / `post_id` / `creator` の抽出は、先頭ブロックのみを上限付き（先頭 64 KiB）で読みます。タイトルとメタブロックは常にファイル先頭にあるため、上限を超える本文の末尾が切り詰められても解析結果には影響せず、コストは本文サイズに比例しません。一方、**本文条件（`body:`）での絞り込み**は `post.md` **全体**を読み込んでから解析します（本文は先頭読みでは原理的に照合できません）。巨大な本文を出力するツールは、本文絞り込み経路での読み込みコストが本文サイズに比例して増える点に留意してください。
- ファイル名・フォルダ名は NAS 互換のため **1 コンポーネント 255 UTF-8 バイト以内**を推奨します。
